## Problem

Dev.to is a syndication/SEO surface (WS1) — canonical reposts, no engagement. The
_engagement_ channels are **IndieHackers** (build-in-public) and **Reddit** (topic
communities). But both punish the one thing the existing distribution system does:
link-drop self-promo. The `social_generate_drafts` atom produces "check out my new post"
promo copy per platform — exactly what gets an account shadow-banned on Reddit and ignored
on IndieHackers. There is no tool that produces **native, community-appropriate,
founder-voice** content for these surfaces, and no representation of the fact that every
subreddit has different rules, self-promo tolerance, and post-type norms.

This is the WS2 workstream flagged as a follow-up when WS1 shipped: the participation play,
draft-only, founder-voice, human-reviewed, no auto-posting.

## Decisions (locked in brainstorming 2026-07-13)

1. **Content model = both, split by target.** IndieHackers = _standalone build-in-public_
   (sourced from real system state + dev*diary, not blog-tied). Reddit = \_native
   per-subreddit value-posts* that reference the blog only when it genuinely helps the
   reader. Two generators, one shared profile/draft/review substrate.
2. **Subreddit handling = DB profiles.** A new `subreddit_profiles` table (greenfield —
   confirmed via git history that no such table ever existed; the prior art is only the
   flat `social_reddit_subreddits` CSV setting + the Reddit `publishing_adapters` row).
3. **Posting = draft-only, operator posts manually.** No Postiz, no auto-post, zero
   account-ban surface. Drafts carry a _mark-posted-with-URL_ state. (IndieHackers has no
   posting API anyway.)
4. **Trigger = on-demand (pull) only.** No scheduled job, no cadence, no unsolicited
   drafts. The operator runs a `poindexter community …` command when they want one.
   Matches `feedback_output_vs_curation` (generate less, curate more) and `feedback_no_popups`.

## Goals / Non-goals

**Goals:** an on-demand, CLI-first assistant that generates a native founder-voice draft
for a chosen surface (a specific subreddit, or IndieHackers), stores it for review/edit,
surfaces each subreddit's constraints as advisory warnings, and records the permalink once
the operator posts manually. Reuse the WS1.5 `post_content_types` axis to match a blog post
to the subreddits it fits.

**Non-goals (this spec):**

- **Posting/automation** — no Postiz integration, no approve→publish, no scheduled
  generation, no cadence digest. Pure pull + manual post.
- **Engagement analytics** — no karma/upvote/comment tracking. (The `posted_url` field
  makes it a cheap follow-up later; not now.)
- **Reusing `social_post_drafts`** — that table is welded to the Postiz publish-gate
  (`approve_draft` refuses unless the post is live; `CancelOrphanedSocialDraftsJob` reaps
  it). WS2's lifecycle is different (manual post, no blog-post dependency), so it gets its
  own table rather than bending that machinery. `feedback_everything_behind_a_seam_is_disposable`:
  a clean separate seam beats a coupled reuse.
- **Console/Telegram review surfaces** — CLI is the MVP (`feedback_cli_first`); a console
  panel / Telegram digest is an explicit later follow-up.
- **Auto-curating the subreddit set** — the operator curates profiles by hand.

## Data model — two new tables (migration)

**`subreddit_profiles`** — the per-community config that makes drafts fit:

```sql
CREATE TABLE IF NOT EXISTS public.subreddit_profiles (
    id                   bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    subreddit            text NOT NULL UNIQUE,        -- 'LocalLLaMA' (no r/ prefix)
    enabled              boolean NOT NULL DEFAULT true,
    content_types        text[] NOT NULL DEFAULT '{}',-- classifier labels this sub takes
    post_type            text NOT NULL DEFAULT 'text',-- 'text' | 'link' | 'either'
    self_promo           text NOT NULL DEFAULT 'strict', -- 'strict' | 'moderate' | 'ok'
    flair                text,                        -- default flair to set (nullable)
    min_karma            integer,                     -- advisory gate (nullable)
    min_account_age_days integer,                     -- advisory gate (nullable)
    rules_summary        text NOT NULL DEFAULT '',    -- rules + culture, fed to the LLM
    tone_notes           text NOT NULL DEFAULT '',    -- how to write for this sub
    cadence_cap_days     integer,                     -- advisory 'don't post here > 1x/N days'
    created_at           timestamptz NOT NULL DEFAULT now(),
    updated_at           timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_subreddit_profiles_enabled ON subreddit_profiles (enabled);
```

Gates (`min_karma`, `min_account_age_days`, `cadence_cap_days`, `self_promo`) are
**advisory** — surfaced to the operator in the draft, never enforced (the operator is the
poster). `content_types` is the match key against `post_content_types` (WS1.5).

**`community_post_drafts`** — the draft store (distinct lifecycle from `social_post_drafts`):

```sql
CREATE TABLE IF NOT EXISTS public.community_post_drafts (
    id             bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    target         text NOT NULL,                     -- 'reddit:LocalLLaMA' | 'indiehackers'
    title          text,                              -- post title (Reddit/IH need one)
    body           text NOT NULL,
    post_type      text NOT NULL DEFAULT 'text',      -- resolved from the profile
    source_post_id uuid REFERENCES posts(id) ON DELETE SET NULL,  -- nullable (IH not blog-tied)
    warnings       text[] NOT NULL DEFAULT '{}',      -- advisory constraints surfaced to operator
    status         text NOT NULL DEFAULT 'draft',     -- draft | posted | discarded
    posted_url     text,                              -- permalink the operator pastes back
    model          text,                              -- which model generated it (provenance)
    created_at     timestamptz NOT NULL DEFAULT now(),
    updated_at     timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_community_post_drafts_status ON community_post_drafts (status);
```

No unique/idempotency key: on-demand generation is deliberate operator action — a second
`draft reddit <post> --subreddit X` is a _new take to compare_, not a dup to suppress.

## Settings (`settings_defaults.py`)

| key                          | default | meaning                                                                                                                                                |
| ---------------------------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `community_draft_model`      | `''`    | model pin for generation; empty → the writer model (`pipeline_writer_model`). Prose founder-voice, so writer-grade, NOT `structured_extraction_model`. |
| `community_ih_lookback_days` | `14`    | how far back to pull system state / dev_diary for an IH build-log.                                                                                     |

Subreddit targeting lives in the `subreddit_profiles` table (operator-curated), NOT a
setting — it's structured multi-field config, not a scalar (`feedback_db_first_config` +
`feedback_filter_on_seams_not_slugs`).

**Seed:** the OSS default is an **empty** `subreddit_profiles` table (a fresh operator adds
their own). Matt's **operator overlay** seeds a small real starter set matched to the brand
niches — e.g. `LocalLLaMA` (`{ai-ml}`, text, strict), `selfhosted`
(`{ai-ml,software-engineering}`, text, strict), `SideProject` (`{founder-meta}`, either,
moderate), `buildapc`/`homelab` (`{pc-hardware}`, text, strict). Real subreddits, not dummy
data (`feedback_no_dummy_data`); operator curates via the CLI or the CSV round-trip (below).
Seeds go in the operator overlay's seed path, OSS `baseline.seeds.sql` stays empty for this table.

## CLI surface (`poindexter community …`) — the primary interface

Thin adapters over `services/community_drafts.py` (`feedback_cli_first` + the
transport-adapter-contract ADR — no business logic / raw SQL in the CLI layer):

- `community profiles list | show <sub> | add <sub> [--content-types …] [--post-type …] [--self-promo …] [--flair …] [--min-karma …] [--rules …] [--tone …] | edit <sub> … | enable <sub> | disable <sub> | rm <sub> | import-csv <path> [--force] | export-csv [path]` — full CRUD + spreadsheet round-trip. Verbs mirror the `poindexter affiliate` group (`add/list/enable/disable/rm/import-csv`) so the UX is consistent.
- `community draft reddit <post-slug-or-id> [--subreddit X]` — generate a native value-post
  for a **published** post. With `--subreddit`: use that profile. Without: **suggest** the
  enabled profiles whose `content_types` overlap the post's `post_content_types` (WS1.5,
  deterministic) and require the operator to pick — never auto-fan-out.
- `community draft ih [--topic "…"]` — standalone build-in-public draft from real system
  state (last `community_ih_lookback_days`: merged PRs, `decision_log`, real metrics) +
  any dev_diary; `--topic` narrows it.
- `community drafts list [--status] | show <id> | edit <id> [--title …] [--body-file …] | mark-posted <id> --url <permalink> | discard <id>`.

### Subreddit profiles — CSV round-trip (`import-csv` / `export-csv`)

So the operator curates in a spreadsheet, never hand-edits DB rows. `services/subreddit_import.py`
mirrors `modules/content/affiliate_import.py::import_csv` (`feedback_no_wheel_reinvention` — reuse
the established pattern):

- `import_csv(pool, csv_path, *, force=False) -> ImportReport` — `csv.DictReader` over a header
  row; columns map 1:1 to `subreddit_profiles` (`subreddit, enabled, content_types, post_type,
self_promo, flair, min_karma, min_account_age_days, rules_summary, tone_notes, cadence_cap_days`).
  `content_types` is a `;`-delimited cell → `text[]`. **Insert-only by default**, keyed on
  `subreddit` — an existing row is `skipped_exists` unless `--force` (then update-in-place, so a
  re-import after a spreadsheet edit lands). Per-row **fail-open**: a malformed row becomes an
  `error` result and the batch continues (one bad row never aborts the import; the report surfaces
  it). No LLM — columns are literal (unlike affiliate's keyword derivation).
- `export_csv(pool) -> str` — dump every profile in the same column layout, so the loop is
  export → edit in a spreadsheet → re-import (`feedback_standard_interfaces`: symmetric
  ingest/export, no proprietary format).
- Both CLI commands are thin adapters; the `ImportReport` (created / skipped / errors, mirroring
  the affiliate importer's dataclass) prints a one-line-per-row summary.

## Generation engines + prompts (SKILL.md packs)

Prompts are auto-discovered SKILL.md packs (`feedback_prompts_must_be_db_configurable`),
category `social_media` (a valid `_CATEGORY_MAP` key), `output_format: text` (prose, not JSON):

- **`skills/community/reddit-value-post/SKILL.md`** (key `community.reddit_value_post`):
  input = post title + content + its `post_content_types`, plus the target profile's
  `rules_summary` / `tone_notes` / `post_type` / `self_promo` / `flair`. Output leads with
  the insight/value; references the blog **only if** `post_type ∈ {link, either}` AND it
  genuinely helps; never a bare link-drop. The atom/service also computes the `warnings[]`
  deterministically from the profile (`self_promo='strict'` → "no link, post as text";
  `min_karma`/`min_account_age_days` → gate reminder; `flair` → "set flair: …";
  `cadence_cap_days` → "you last drafted/posted here N days ago" if derivable).
- **`skills/community/indiehackers-buildlog/SKILL.md`** (key `community.indiehackers_buildlog`):
  input = real system state (shipped PRs / decisions / metrics over the lookback window) +
  optional `--topic`. Output = founder-voice build-log. **No fabricated numbers** — every
  figure comes from a real source row (`feedback_no_dummy_data`, `feedback_no_hardcoded_lengths_in_prompts`).

**Model:** writer-grade local (`pipeline_writer_model`, gemma-4-31B — `feedback_model_selection`),
overridable via `community_draft_model`; local default (`feedback_no_paid_apis`).

**Voice/guardrails:** first-person founder-voice = the operator's own voice (they post under
their own account, so no bot attribution — `feedback_content_voice`). Run the anti-LLM-tells
ban (`feedback_writing_anti_llm_tells` — delve/tapestry/testament, sentence variety, firm
stances) and no-satire (`feedback_no_satire`). Amplify first-party knowledge, never a
zero-value rewrite (`feedback_amplify_operator_knowledge`).

## Content-type matching (WS1.5 synergy)

`community draft reddit <post>` with no `--subreddit` runs a deterministic match:
`SELECT subreddit FROM subreddit_profiles WHERE enabled AND content_types && (post's post_content_types)`
(`&&` = array overlap). The operator picks from the suggested set. Deterministic, no LLM
for routing (`feedback_calculated_vs_generated`). A post the classifier hasn't labelled yet
suggests nothing → the operator passes `--subreddit` explicitly.

## Testing (`feedback_docs_and_tests_default`)

**Unit** (mocked pool + LLM):

1. `subreddit_profiles` CRUD service functions.
2. Content-type match: post labelled `{ai-ml}` suggests only `content_types && {ai-ml}` profiles.
3. Reddit generation: draft stored; blog link OMITTED when `post_type='text'`, present when
   `'link'/'either'`.
4. Warnings computed from a profile (`self_promo='strict'`, `flair`, `min_karma`).
5. IH generation from a stubbed system-state bundle; no number appears that isn't in the input.
6. `mark-posted` sets status+url; `discard` sets status.
7. CSV import: a row round-trips into a profile; a second import of the same `subreddit` is
   `skipped_exists` unless `--force` (which updates in place); a malformed row → `error` and the
   batch continues; the `;`-delimited `content_types` cell parses to the array; `export_csv` →
   `import_csv` is idempotent.

**Integration_db** (real Postgres): both tables' shape; a profile insert + a draft round-trip
(generate with stubbed LLM → row present → mark-posted → status/url persisted); a CSV
export→import round-trip against real Postgres preserves every column incl. `content_types[]`.

**Docs:** the two SKILL.md packs; `docs/architecture/community-draft-assistant.md` (product-
generic — no operator identity / internal issue refs, per `feedback_no_operator_info_to_public_repo`).

## Verification (before merge)

1. Unit + integration_db green (worktree venv, `-o addopts=""`).
2. Seed one real profile locally, run `community draft reddit <a real ai-ml post>` — eyeball
   that it's a genuine value-post, not a link-drop, and the warnings are right.
3. `community draft ih` over the last 2 weeks of real system state — eyeball that every
   number traces to a real source and the voice reads as founder, not LLM.

## Decomposition / phasing

One coherent feature, built in two reviewable increments (shared table+CLI+service land in
the first):

- **PR1** — the schema migration (both tables), `settings_defaults`, `services/community_drafts.py`
  (profiles CRUD + draft CRUD + Reddit generation + content-type match), `services/subreddit_import.py`
  (CSV import/export, mirroring `affiliate_import`), the reddit-value-post SKILL.md, the
  `poindexter community` CLI (full `profiles` CRUD + `import-csv`/`export-csv`, `draft reddit`,
  `drafts`), unit + integration_db tests, architecture doc.
- **PR2** — IndieHackers generator (`community draft ih`), the indiehackers-buildlog
  SKILL.md, system-state sourcing, its tests. Reuses PR1's table + CLI group + review path.

Operator-overlay subreddit seeds land in the stripped overlay, not OSS baseline. WS2 stays
independent of any future Postiz-posting decision (that would be a separate opt-in behind
the `posted_url`/target seam).
